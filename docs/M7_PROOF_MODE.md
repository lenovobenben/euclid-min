# M7 Proof Mode：有界下界证明

本文定义 `regular-17-e-fixed-v1` 的下界证明路线。当前 19 E 证书给出

\[
\operatorname{OPT}\le 19.
\]

要证明 19 是真正最小值，还必须证明不存在分数不超过 18 E 的合法程序，即

\[
\operatorname{OPT}>18.
\]

M7 的目标是让这个否定结论来自可审计的安全归约和完备枚举，而不是 beam、
浮点排名、候选宽度、运行时超时或未校准的启发式。

## 1. 当前 P0/P1 交付物

P0 已实现一个小深度 proof-mode 闭环，P1 在此基础上加入第一项非平凡安全归约：

- `euclid_min.search.proof` 按 E-score 做确定性完整分层枚举；
- `euclid-min-bounded-proof/v1` 记录每层 frontier、候选、合并和目标检查计数；
- `euclid-min prove` 生成证明记录；
- `euclid-min check-proof` 使用另一套线性精确候选去重和状态索引重新枚举；
- 生成与检查均固定到 profile ID 及其已发布 SHA-256；
- proof mode 不接受 `max_states`、超时、beam 或浮点候选删除。
- 关于横轴互为镜像的状态被合并为一个精确等价轨道；
- 目标依赖祖先审计可以识别并裁剪不服务于目标根的计费对象。

当前实现只证明实际完成的小深度分数界，不证明 18 E 已被穷尽，也不改变当前
“19 E 已验证上界”的结论等级。

## 2. 有界枚举的完备性

设深度为 \(d\) 的 frontier 已包含所有成本恰为 \(d\) 的不同可达数学状态。
对每个状态，proof mode：

1. 精确排序完整点集；
2. 枚举每个无序不同点对产生的直线；
3. 枚举每个有序不同点对产生的基础圆；
4. 对每个不同新对象执行全部既有对象的自动有限实交点闭包；
5. 精确检查目标；
6. 只按已经证明安全的等价关系合并状态。

因此每个合法的下一步新对象都由候选生成器覆盖。对深度归纳后，若分数
\(0,\ldots,d\) 的全部 frontier 均已完成且没有目标状态，就可以推出不存在
分数不超过 \(d\) 的合法构造。

## 3. 当前启用的安全归约

### 3.1 重复绘制支配

当前 profile 允许重复画出已有对象，但该操作消耗 1 E，既不增加对象，也不重新
产生交点。如果一个命中程序包含重复绘制，删除该步不会降低后续状态能力，并会
得到更短程序。因此最短构造不含重复绘制，完备最短路枚举可以排除它。

### 3.2 同一对象的参数化等价

同一条直线可能由多对共线点生成，同一个圆也可能由不同圆上点参数化。若基础
操作得到的数学对象相同，则成本、加入后的对象集合和自动交点闭包完全相同。
候选生成只保留确定性顺序中的第一个表示，不会删除不同的后继状态。

### 3.3 精确状态等价

正式模型的未来能力只由去重后的 (S=(P,L,C)) 决定。两个历史若得到完全相同的
点、线、圆集合，则后续合法候选、每个候选的闭包和目标结果相同。保留成本不高的
一个代表即可。

优化枚举器可以用数值投影把对象放入比较桶，但桶命中后必须精确确认；摘要碰撞
不能合并不同对象。参考 checker 不使用这种摘要做候选或状态去重，而是对全部
已有项进行线性精确比较。

### 3.4 横轴反射等价

定义精确反射

\[
\sigma(x,y)=(x,-y).
\]

它固定初始点 (O,A) 和单位圆，把 (B_+) 与 (B_-) 互换，并满足：

- 两点连线的像等于两像点的连线；
- 以一点为圆心、经过另一点的圆的像等于以两像点定义的圆；
- 有限实交点集合在反射下逐点对应；
- 每项操作成本保持为 1 E。

所以若状态 \(S\) 可在剩余 \(k\) 步命中任一允许目标，则 \(\sigma(S)\) 也可在
\(k\) 步命中镜像目标。Proof mode 可以只保留每个二元反射轨道的一个代表。

优化索引用状态及其镜像两个非权威摘要中的较小者分桶，桶内仍做精确原状态或
精确镜像状态比较；参考 checker 完全不使用摘要去重。深度 3 的固定对照中，
接受状态从未归约的 188 个降到 116 个，下降约 38.3%；最终 frontier 从 172 个
降到 104 个。

### 3.5 最后一步目标入射

对一个尚未命中的状态，设下一步加入新对象 \(D\)。所有新交点都位于 \(D\) 上；
另一方面两个允许目标从初始时刻起就位于免费单位圆上。因此：

\[
\text{下一步首次命中目标}
\quad\Longleftrightarrow\quad
D\text{ 精确经过 }B_+\text{ 或 }B_-.
\]

证明分数不超过 \(d\) 时，proof mode 仍完整生成深度 \(d-1\) 每个状态的全部不同
候选，但只对精确经过目标的候选构造深度 \(d\) 子状态。未经过目标的候选不可能在
最后一步成功，可以安全计入 `terminal_nonmatching_pruned`。

参考 checker 使用自己的完整候选生成器并重复同一个精确入射判断。当前 4 E 固定
记录在深度 3 的 104 个镜像归约状态上完整检查 4,173 个末步候选；全部不经过
目标，因此无需为这些候选构造任何深度 4 的精确交点闭包。

## 4. 目标依赖祖先定理

给定一个成功程序，把首次产生目标的计费对象作为目标根。当前目标始终位于免费
单位圆上，所以目标首次出现时，新画对象必定经过 (B_+) 或 (B_-)，并与单位圆
共同产生目标。

对程序递归定义直接依赖：画线或圆依赖其两个输入点，交点名称依赖两个相交对象。
若某个计费对象不在目标根的递归祖先闭包内，则删除它和所有非祖先名称后：

- 目标根的每个输入仍由保留的对象对产生；
- 保留条目的拓扑引用仍合法；
- 目标根及单位圆仍产生同一目标；
- E-score 严格下降。

因此最短成功程序的每个计费对象都必须属于某个首次目标根的依赖祖先闭包。
`euclid_min.search.dependencies` 已实现直接依赖表、祖先闭包、裁剪和首次目标根
审计。现有 19 E 证书的首次目标根为 `target_line`，全部 19 个计费对象均在其
祖先闭包内。

该定理目前用于审计和下一阶段反向 DAG 设计，尚未作为前向 proof 枚举的即时
剪枝；在 proof record 中只声明实际参与状态合并的归约。

## 5. 证明记录

Schema 位于 `schemas/bounded-proof-v1.schema.json`。记录固定包含：

- profile ID 与规范摘要；
- 目标集合和 E-score 上界；
- 精确算术、完整候选生成及禁用启发式的声明；
- 当前启用的安全归约 ID；
- 每层 frontier 数量、目标状态数、完整候选数、精确等价合并数和终层入射计数；
- 总展开数、总候选数、总接受状态数和目标检查数；
- `exhausted` 或 `found` 结论。

记录故意不包含墙钟时间，因为时间不是数学证明的一部分。生成记录本身也不受
信任；`check-proof` 从初始状态重新完成参考枚举，并逐字段比较重放结果。

## 6. 使用方式

生成一份小深度证明记录：

```bash
sage -python -m euclid_min prove \
  --profile profiles/regular-17-e-fixed-v1.yaml \
  --max-score 4 \
  --output proofs/regular-17-through-4e.json \
  --json
```

使用参考 checker 重放：

```bash
sage -python -m euclid_min check-proof \
  --profile profiles/regular-17-e-fixed-v1.yaml \
  proofs/regular-17-through-4e.json \
  --json
```

`prove` 成功生成记录时返回 0；`check-proof` 重放一致时返回 0，不一致时返回 1。
仓库中的 `proofs/regular-17-through-4e.json` 是首份固定产物；它证明当前
profile 下 0–4 E 均不能命中相邻顶点，用于校准格式、镜像归约、终层约束和重放链路。

## 7. 可信边界

参考 checker 与生成器具有不同的候选去重和状态索引实现，但仍共享：

- SageMath `AA`；
- Point、Line、Circle 和三类精确求交；
- 自动交点闭包；
- 正十七边形精确目标实现。

因此它比重复运行同一搜索入口更强，但还不是 Lean 或其他证明助理检查的形式化
定理。最终若要进一步缩小可信代码基础，可以让 Sage 输出多项式、实根隔离区间
和有限枚举证书，再由更小的独立 checker 或 Lean 验证；M7 第一阶段不依赖 Lean。

## 8. 尚未完成的关键工作

线性参考重放只适合小深度。通向 18 E 的下一阶段依次为：

1. 把最后一步入射条件递归展开为反向依赖 DAG 搜索；
2. 设计前向状态与多步反向目标约束的 meet-in-the-middle 接口；
3. 给并行分片增加确定性覆盖范围和可合并证明记录；
4. 先完整重放固定 E12/E16 局部窗口，再评估全局 18 E；
5. 只有所有分支都由安全规则覆盖后，才允许发布 `OPT = 19`。

任何候选 shortlist、beam width、浮点阈值、随机重启或超时负结果都继续属于
`heuristic_nonproof`，不得写入下界证明。
