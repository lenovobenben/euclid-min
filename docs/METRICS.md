# Euclid-Min E 步计分规范 v1

本文定义 `regular-17-e-fixed-v1` 的唯一正式指标：E 步（E-move，elementary move）。本文是规范性文件；介绍性文字、动画脚本和人工步数都不能覆盖这里的规则。

## 1. 一句话定义

构造程序的 E 分数为

\[
E=\#\operatorname{Line}+\#\operatorname{Circle}
\]

也就是：**每实际画一条合法直线计 1 E，每实际画一个合法基础圆计 1 E；点和交点不计 E。**

| 程序条目 | 成本 |
|---|---:|
| `line` | 1 E |
| `circle` | 1 E |
| `intersect` | 0 E |
| 初始对象 | 0 E |
| 自动交点闭包 | 0 E |

## 2. 两种计费操作

### 2.1 直尺

`line(P,Q)` 的前提是 \(P,Q\) 都是当前状态中的已有点且 \(P\ne Q\)。结果是经过这两个点的整条直线，成本为 1 E。

### 2.2 可折叠圆规

`circle(P,Q)` 的前提是 \(P,Q\) 都是当前状态中的已有点且 \(P\ne Q\)。结果是以 \(P\) 为圆心、经过 \(Q\) 的圆，成本为 1 E。

当前规则不允许一步执行“以 \(C\) 为圆心、以 \(|AB|\) 为半径画圆”，除非 \(C\) 就是 \(A,B\) 中的一个端点。把已经量得的距离搬到另一个圆心属于不折叠圆规能力，必须用基础操作展开。

## 3. 初始对象

以下对象免费：

- \(O=(0,0)\)；
- \(A=(1,0)\)；
- 以 \(O\) 为圆心、经过 \(A\) 的单位圆 `unit_circle`。

它们不作为隐含历史步骤计分。改变免费初始对象就改变了研究问题，必须使用新的规则配置，不能沿用当前分数比较。

## 4. 点与交点为什么是 0 E

每画出一个新对象后，验证器把它与所有已有直线和圆精确求交，并把全部有限实交点加入状态。这个闭包过程不使用直尺或圆规画出新对象，因此计 0 E。

`intersect` 条目只是在这些已经存在的交点中确定性地选择并命名一个点，也计 0 E。给同一个数学点绑定多个别名仍然不计分。

本项目不允许通过 0 E 条目任取新点。除初始点外，新点只能来自：

- 两条已有直线的交点；
- 已有直线与已有圆的交点；
- 两个已有圆的交点。

## 5. 高级宏必须展开

以下名称都不是当前规则中的基础一步：

- 中点；
- 垂线或垂足；
- 垂直平分线；
- 平行线；
- 角平分线；
- 对称点；
- 距离搬运。

如果界面、搜索器、论文或人类说明使用这些宏，正式计分前必须完全展开成 `line`、`circle` 和零成本的 `intersect` 条目。宏名称本身没有分数，也不能把整段宏笼统算成 1 E。

## 6. 例子：构造中点

只免费给出两个不同点 \(P,Q\)，目标是构造线段中点：

1. 画直线 \(PQ\)：1 E；
2. 画以 \(P\) 为圆心、经过 \(Q\) 的圆：1 E；
3. 画以 \(Q\) 为圆心、经过 \(P\) 的圆：1 E；
4. 两圆交点 \(U,V\) 自动出现：0 E；
5. 画直线 \(UV\)：1 E；
6. \(PQ\) 与 \(UV\) 的交点自动出现，它就是中点：0 E。

总分为 4 E。若直线 \(PQ\) 也是免费初始对象，第一步可以省去，总分变为 3 E。这个例子同时说明：图中看起来相同的任务，只要初始对象不同，分数就不能直接比较。

## 7. 重复画图

再次画出数学上已经存在的直线或圆，仍然消耗 1 E。计分对象是程序实际执行的画图动作，不是最终图中不同对象的数量。

例如，一份程序先后两次执行同一对点的 `line`，状态中只有一条数学直线，但分数增加 2 E。

验证报告必须区分：

```text
draw_operations.lines
draw_operations.circles
draw_operations.total
distinct_objects.lines
distinct_objects.circles
duplicate_draws
```

正式 E 分数使用 `draw_operations.total`。

## 8. 计分对象与验证责任

计分针对证书中完整、有序的 `construction.program`。

验证器必须自己逐条检查并计数，不得信任证书中的 `assertions.score.e_move`。声明分数与重算分数不同，证书验证失败并返回 `score_assertion_mismatch`。

非法程序没有正式分数。验证器可以报告错误发生前已经消耗的 E 步和错误位置，但这些只是诊断数据，不能参与构造比较。单条非法 `line` 或 `circle` 在前置条件校验失败时不计入诊断分数。

## 9. 目标提前出现

如果目标在第 \(k\) 次画图后出现，但程序之后还有合法画图步骤：

- `first_target_e_move` 为 \(k\)；
- 正式 `score.e_move` 仍是完整程序中的全部画图次数；
- 验证器不会自动截断或忽略后续步骤。

发布短构造时，应提交在首次命中目标后立即结束的裁剪版本。

## 10. 可比性

两个 E 分数只有同时满足以下条件时才能直接比较：

- 规则配置 ID 相同；
- 规则配置内容哈希相同；
- 两份程序都通过精确验证；
- 分数都由符合本规范的验证器重新计算。

只要初始对象、自由点规则、圆规模型、目标条件或指标不同，就不是同一个问题。不同规则下的数字只能并列说明，不能写成直接的优劣关系。

## 11. 名称与文献依据

本项目的计费核心有明确的公开先例。

### 11.1 Labelle 计数

François Labelle 在 1997 年的 [*The Complexity of Geometric Constructions*](https://www.cs.mcgill.ca/~sqrt/cons/constructions.html) 中规定：

- 直尺经过两个已构造点画线；
- 可折叠圆规以一个已构造点为圆心、经过另一个已构造点画圆；
- 直线和圆的交点视为已构造点；
- 复杂度就是执行的画线与画圆次数。

这与本项目的基础操作和计费公式相同。

Sava Grozdev 与 Deko Dekov 的 2015 年论文 [*The Computer Improves the Steiner’s Construction of the Malfatti Circles*](https://azbuki.bg/wp-content/uploads/2015/02/azbuki.bg_dmdocuments_MathInfo012015_Grozdev_Dekov.pdf) 明确采用 Labelle 指标。论文表格把画一条线或一个圆记为 1，把交点记为 0，并用这一指标比较 Malfatti 圆构造。

### 11.2 E 步名称

Erik D. Demaine 与 Victor Luo 的 2025 年论文 [*Euclidea is APX-hard: Complexity of Optimizing Euclidean Constructions*](https://doi.org/10.2197/ipsjjip.33.1110) 正式定义：

- 一次直尺工具或圆规工具的使用是一个 E-move；
- 直尺经过两个点画线为 1 E；
- 圆规以一个点为圆心、经过另一个点画圆为 1 E；
- 解的 E-score 不包含点定义。

本项目采用“E 步”名称，并沿用这一基础计费方式。

### 11.3 相同计费核心不等于相同规则配置

Demaine–Luo 的一般模型还讨论任意点和半自由点；Grozdev–Dekov 的具体问题具有自己的初始图形；Labelle 页面中的各道题也有各自给定对象。本项目则固定单位圆、\(O,A\)，并禁止任意点和半自由点。

因此可以严格说“本项目采用与上述资料相同的基础画图计数原则”，但不能仅凭这一点把它们报告的分数与 19 E 直接比较。

## 12. 与 Lemoine 简洁度的区别

Lemoine 简洁度把直尺或圆规的放置、对准和实际绘制拆成多类动作并分别计数。DeTemple 1991 的正十七边形修改构造报告 45，是这一历史指标下的分数，不是 45 E。

本项目把 DeTemple 路线展开并转换到当前规则后得到的 32 E 和 19 E，只能在 `regular-17-e-fixed-v1` 内部比较；原文的 51/45 与本项目的 32/19 不能跨指标比较。

## 13. 正式报告最小字段

成功验证的报告至少包含：

```json
{
  "valid": true,
  "draw_operations": {
    "lines": 0,
    "circles": 0,
    "total": 0
  },
  "score": {
    "metric": "e_move",
    "e_move": 0
  },
  "first_target_e_move": 0,
  "target": ["B_plus"]
}
```

上例中的零值只说明字段结构，不代表存在零步构造。
