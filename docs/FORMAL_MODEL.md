# Euclid-Min 正式模型 v1

本文是 `regular-17-e-fixed-v1` 的规范性语义说明。实现必须同时满足本文、对应 profile、`METRICS.md` 和 `CERTIFICATE_FORMAT.md`。

## 1. 规范用语与优先级

“必须”“不得”“应当”“可以”分别表示强制要求、强制禁止、推荐要求和允许选择。

发生冲突时，按以下优先级解释：

1. profile ID 对应的已发布 profile 内容；
2. profile 和 certificate JSON Schema；
3. 本文；
4. `METRICS.md` 与 `CERTIFICATE_FORMAT.md` 中各自负责的专门规则；
5. `euclid-min-design.md` 中的研究设计和非规范示例。

任何会改变合法构造集合、目标集合或分数的修改，都必须产生新的 profile ID。仅补充不改变语义的文字说明，可以保留原 profile ID，但必须记录版本变更。

## 2. 固定实例

坐标平面是实欧氏平面。当前 profile 固定：

\[
O=(0,0),\qquad A=(1,0),\qquad \Gamma:x^2+y^2=1.
\]

初始数学状态包含：

- 点 (O)；
- 点 (A)；
- 圆 (Gamma)，证书 ID 为 `unit_circle`。

初始对象免费提供。初始点已经属于初始圆，不需要也不会产生额外的交点定义步骤。

## 3. 精确数域

所有坐标和几何判断都在实代数数域中进行。参考实现使用 SageMath 的 Algebraic Real Field `AA`。

规范要求精确支持：

- 四则运算；
- 精确平方根；
- 等于和不等于；
- 严格小于、等于、严格大于；
- 多项式表达式的精确符号判断。

浮点近似不得用于决定：

- 两个点是否相同；
- 输入点是否不同；
- 两个对象是否相同或重合；
- 交点个数；
- 相切、平行和退化情况；
- 交点排序；
- 目标是否出现。

## 4. 数学对象

### 4.1 点

点是有序对：

\[
P=(x,y),\qquad x,y\in\overline{\mathbb{Q}}\cap\mathbb{R}.
\]

两个点相同，当且仅当它们的两个坐标分别精确相等。点的证书 ID 只是别名，不参与数学身份判断。

### 4.2 直线

直线表示为非零三元组的比例等价类：

\[
L=[a:b:c],\qquad ax+by+c=0,qquad (a,b)\ne(0,0).
\]

两个直线相同，当且仅当它们的系数三元组精确成比例。实现可以选择规范化形式加速比较，但 hash 或字符串相同不得替代最终的精确等价判断。

由两个不同点 (P=(x_1,y_1))、(Q=(x_2,y_2)) 生成的直线可以使用：

\[
a=y_1-y_2,\quad b=x_2-x_1,\quad c=x_1y_2-x_2y_1.
\]

### 4.3 圆

圆表示为：

\[
C=(u,v,r^2),\qquad (x-u)^2+(y-v)^2=r^2,qquad r^2>0.
\]

两个圆相同，当且仅当圆心坐标和半径平方分别精确相等。

内部应优先保存 `radius_squared`，避免无必要的平方根。

## 5. 数学状态与名称环境

执行状态由两部分组成：

```text
数学状态 S = (P, L, C)
名称环境 N = ID 到数学对象的映射
```

其中 (P,L,C) 分别是去重后的点、直线和圆的集合。名称环境允许多个不同 ID 指向同一个数学对象。

所有程序条目的 `id` 处于同一个全局命名空间，并且必须唯一。初始 ID `O`、`A`、`unit_circle` 已被占用，不得重新声明。

ID 必须匹配：

```text
^[A-Za-z][A-Za-z0-9._-]*$
```

ID 不决定对象的数学身份，也不得被用于交点排序。

## 6. 基础作图操作

### 6.1 画直线

```text
Line(P, Q)
```

前置条件：

- `P` 和 `Q` 已在名称环境中绑定为点；
- `P` 与 `Q` 的数学坐标不相同。

结果为唯一通过两点的直线，成本为 1 E-move。

### 6.2 画圆

```text
Circle(center=P, through=Q)
```

前置条件：

- `P` 和 `Q` 已在名称环境中绑定为点；
- `P` 与 `Q` 的数学坐标不相同。

结果为以 (P) 为圆心、以 (|PQ|) 为半径的圆，成本为 1 E-move。

当前 profile 不提供 `Circle(center=C, radius=AB)` 形式的距离直接搬运。若圆心不是距离的端点，必须展开为基础操作。

### 6.3 重复对象

如果一个合法画线或画圆操作得到的对象在数学状态中已经存在：

- 本次操作仍计 1 E-move；
- 新 ID 绑定到已经存在的数学对象；
- 数学状态不增加新的直线或圆；
- 不执行新的交点闭包，也不产生新点。

“重复”不是非法操作，只是搜索时通常可排除的受支配操作。

### 6.4 非法操作

以下情况使整个构造程序验证失败：

- 引用尚未声明或类型不正确的 ID；
- 使用数学上相同的两个点画线；
- 使用数学上相同的圆心和圆上点画圆；
- 重复声明 ID；
- 使用 profile 未启用的操作；
- 交点绑定不满足第 8 节规则。

验证器应返回首次失败的位置和稳定的错误代码。非法程序没有正式 E-score；实现可以额外报告失败前已经消费的操作数，但必须标记为诊断值。

## 7. 自动交点闭包

每次得到一个此前不存在的新直线或新圆后，验证器必须：

1. 将新对象与操作前已经存在的每一个不同直线和圆分别求交；
2. 对每一对象对计算全部有限实交点；
3. 按第 9 节进行精确排序；
4. 按精确坐标把交点加入点集 (P)；
5. 已经存在的点不重复加入数学状态。

交点生成是自动的，不计 E-move。新产生的点即使尚未获得证书别名，也已经属于数学状态。

如果新对象是重复对象，不重新计算它与已有对象的交点，因为这些对象对在更早状态中已经闭包。

当前 profile 不添加无穷远点，也不保留复交点。

## 8. 交点绑定

证书中的 `intersect` 条目不是新的尺规操作，而是给自动闭包中已经存在的一个交点绑定名称，成本为 0 E-move。

绑定条目指定两个此前已命名的直线或圆，以及该对象对的交点排序索引：

```json
{
  "id": "P",
  "op": "intersect",
  "objects": ["c1", "unit_circle"],
  "index": 1
}
```

绑定合法，当且仅当：

- 两个对象 ID 都已声明，并分别指向直线或圆；
- 两个数学对象不相同；
- 两对象具有至少 `index + 1` 个不同的有限实交点；
- 所选点已经因自动闭包存在于当前数学点集。

`index` 从 0 开始。允许不同 ID 绑定到同一个数学点。

对象引用顺序不影响交点顺序。验证器必须先按数学对象求交，再按坐标排序；不得使用求根器的返回顺序。

重合直线或重合圆具有无穷多个公共点，不提供可绑定的孤立交点。用两个指向同一数学对象的别名进行 `intersect` 必须失败。

## 9. 交点分类与排序

### 9.1 分类

验证器必须精确区分：

- 直线—直线：平行、重合或一个有限实交点；
- 直线—圆：零个、一个相切点或两个不同实交点；
- 圆—圆：分离、内含不交、内切、外切、两个不同实交点或重合。

“一个交点”必须只返回一个数学点，不能把重根返回两次。

### 9.2 排序

一个对象对的不同有限实交点使用精确字典序排序：

1. 先按 (x) 坐标从小到大；
2. 若 (x) 精确相等，再按 (y) 坐标从小到大。

排序后的第一个点索引为 0，第二个点索引为 1。

`left`、`right`、`lower`、`upper` 可以出现在人类可读报告中，但不属于 v1 证书的规范选择器。

## 10. 目标条件

定义：

\[
B_+=\left(\cos\frac{2\pi}{17},\sin\frac{2\pi}{17}\right),
\qquad
B_-=\left(\cos\frac{2\pi}{17},-\sin\frac{2\pi}{17}\right).
\]

构造达到目标，当且仅当数学点集 (P) 中至少存在一个点，与 (B_+) 或 (B_-) 的坐标分别精确相等。

目标点不要求先通过 `intersect` 条目获得名称；自动闭包使它出现时，目标已经达到。验证报告应给出：

- 命中的目标：`B_plus`、`B_minus` 或二者；
- 首次命中发生在哪个画图步骤之后；
- 首次命中时累计的 E-move；
- 完整程序的正式 E-score。

搜索器不得把 (B_+) 或 (B_-) 当作可用输入点。目标坐标仅供验证器判断。

## 11. 顺序执行语义

程序严格从前到后执行。每个条目按以下顺序处理：

### 11.1 `line` 或 `circle`

1. 校验条目结构、ID 唯一性和输入引用；
2. 精确校验操作前置条件；
3. 增加 1 E-move；
4. 构造数学对象；
5. 若为重复对象，仅建立 ID 别名；
6. 若为新对象，将其加入数学状态并执行自动交点闭包；
7. 检查目标是否首次出现。

### 11.2 `intersect`

1. 校验条目结构、ID 唯一性和对象引用；
2. 精确求得对象对的有序有限实交点；
3. 校验索引；
4. 校验所选点已经存在于数学状态；
5. 建立点 ID 别名；
6. 不改变分数。

程序结束时，只要程序合法且目标已经出现，就是一个有效构造。目标出现后的额外合法步骤允许存在，但全部计入正式分数。

## 12. 状态等价与搜索

在当前 profile 中，搜索的数学状态是去重后的三元组 (S=(P,L,C))。如果两个操作历史得到完全相同的三个数学集合，则它们对未来合法基础操作具有相同能力。

搜索器可以合并这种状态，但必须：

- 用精确对象比较确认相等；
- hash 只作为索引加速；
- 保存成本不劣的前驱；
- 保留足够 provenance 以恢复证书。

镜像对称、dominance 和其他剪枝只有在规则被证明保持初始对象、目标集合、合法操作和分数后，才能用于完备搜索。

## 13. 确定性要求

给定相同 profile 和相同证书，符合规范的验证器必须得到相同的：

- 合法或非法结论；
- 首个错误条目和规范错误类别；
- 去重后的对象数量；
- E-score；
- 首次目标命中步骤；
- 精确目标身份。

对象的内部表达式、缓存策略、日志文字和非规范性能数据可以不同。

## 14. 建议错误代码

v1 参考验证器应优先使用以下稳定代码：

```text
schema_invalid
profile_id_mismatch
profile_hash_mismatch
duplicate_id
unknown_reference
wrong_reference_type
coincident_input_points
unsupported_operation
coincident_intersection_objects
intersection_index_out_of_range
intersection_not_in_state
score_assertion_mismatch
target_assertion_mismatch
construction_hash_mismatch
target_not_reached
```

以后可以新增错误代码，但不得在不升级格式版本的情况下改变已有代码的含义。
